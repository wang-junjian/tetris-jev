# 决策路径禁止代码估值（Jev 驱动）

项目目标不是"玩到最牛"，而是验证"代码枚举 + 模型判断"范式：Jev 自己把俄罗斯方块玩好。因此决策路径中一切好坏判断必须来自 Jev，代码只做三件事——枚举合法落点、模拟后果、词化输入。词化可包含客观比较事实（唯一/最高/最低/排名，须可由 state 复算），但禁止方向性评价词和估值结果（启发式分数及其衍生物）。Dellacherie 启发式只允许出现在对照玩家和离线劣招标注中，永不进入决策路径。

## Considered Options

- **代码估值的 2 步前瞻**（900 种两跳组合本地模拟打分，把最优后续喂给 Jev）：棋力收益最大，但智能实际上转移到了代码，Jev 沦为界面——否决。
- **纯启发式玩家直接作为默认 AI**：最强且零成本，但那样项目就没有存在意义——仅保留为对照玩家。

## Consequences

- 接受 Jev 驱动下的棋力天花板可能低于纯启发式；改进手段限于 state 组织、问题设计、选项描述（词化）。
- 未来任何"让代码算一下哪个落点更好再告诉 Jev"的提议，默认拒绝，除非显式推翻本 ADR。
